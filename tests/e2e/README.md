# e2e (Playwright)

Browser tests that click through the real app. Two suites:

| Command | Needs | What it covers |
|---|---|---|
| `npm run e2e` | nothing | Demo mode (no database): the whole inbox loop, role homes, the deputy taking over a late case, every page at phone width. Safe for CI. |
| `npm run e2e:db` | Postgres + `.env.local` with `ADMIN_ACCESS_CODE` | Creates a throwaway company in `/admin`, logs in with personal codes, runs the loop across real sessions, Settings -> Members, then deletes the company. |

Both build the app and start it on their own port (`:3100` demo, `:3101` database), so your
`npm run dev` on `:3000` can keep running. The first run of the day takes a minute or two because
of the build.

## First time

```bash
npm install
npx playwright install chromium
```

## Everyday use

```bash
npm run e2e                          # all demo tests, headless
npm run e2e -- --project=desktop     # skip the phone-width checks
npm run e2e -- -g "whole loop"       # only tests whose name matches
npm run e2e:ui                       # the Playwright window: pick a test, watch it, time-travel each step
npm run e2e -- --headed              # watch the browser while the tests run
npx playwright show-report           # the HTML report of the last run (opens by itself on a failure)
npx playwright show-trace test-results/<test>/trace.zip   # step through a failed test
```

When a test fails, `test-results/<test>/` holds a screenshot and a trace; the trace shows the page
before and after every step.

## Writing a test

- Demo tests go in `tests/e2e/demo/*.spec.ts`, database tests in `tests/e2e/db/*.spec.ts`.
- Import `test` and `expect` from `../helpers`, not from `@playwright/test`: that `test` fails on
  any uncaught error in the page.
- Find things the way a person does: `getByRole("button", { name: "Send the no" })`, `getByText(...)`.
  Not CSS classes - they are generated by CSS Modules and change.
- `npx playwright codegen http://localhost:3100/acme` opens a browser and writes the locators for
  what you click (start the demo server first, e.g. with `npm run e2e:ui`).
- Demo tests each start with an empty localStorage, so they do not see each other's cases.
- Database tests must clean up after themselves - see `company-login.spec.ts`'s `afterAll`.
